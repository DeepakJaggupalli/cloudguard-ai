# CloudGuard AI — Automated Anomaly Detection & Self-Healing Infrastructure

Hackathon prototype for BNP Paribas: cross-layer (VM + application) anomaly
detection, business-impact prioritization, guided/auto remediation, and a
continuous operator-feedback learning loop.

## One-command start

```bash
docker compose up --build
```

- Backend (FastAPI): http://localhost:8000 — Swagger/OpenAPI at **http://localhost:8000/docs**
- Frontend (React dashboard): **http://localhost:5173**
- Health: http://localhost:8000/health

No secrets required — everything runs on the synthetic/provided CSV datasets in `backend/dataset/`. No real production data is used (see Guardrails in the problem statement).

## Architecture

```
Training CSVs (vm_monitoring_train_8000.csv, vm_events_remedies_train_8000.csv)
        |
        v
   MLEngine.train()  --> IsolationForest (anomaly score)
                     --> GradientBoostingClassifier (remediation action)
        |
        v
TelemetryProducer (synthetic VM+app stream, periodic anomaly injection)
        |
        v
TelemetryStore.ingest()  -- validate -> dedup --+-- valid -> in-memory store
                                                 +-- invalid/dup -> Dead Letter Queue (counters)
        | (valid records)
        v
_on_valid_record()  --> ml_engine.predict_anomaly_score()
        |
        v
PriorityEngine.classify()  (config/priority_rules.yaml, P1-P4, cross-layer boost)
        |
        v
correlation.correlate()  (which VM-layer + app-layer metrics breached together)
        |
        v
StateDatabase.create_incident_from_scoring()  --> Incident (REST) + WebSocket push
        |
        v
Frontend dashboard  --> operator: "Perform Remedy" / "True/False Positive"
        |                              |
        v                              v
 /api/incidents/{id}/remediate   /api/incidents/{id}/feedback
                                        |
                                        v
                          ml_engine.record_feedback() -> buffered
                                        |
                          POST /api/models/retrain
                                        |
                                        v
                    MLEngine.retrain_model() -- refits IsolationForest on
                    train data + feedback, reports before/after precision/recall/F1
```

## ML models

| Model | Type | Trained on | Purpose |
|---|---|---|---|
| Isolation Forest | `sklearn.ensemble.IsolationForest` | `vm_monitoring_train_8000.csv`, 9 telemetry features | Unsupervised anomaly scoring (0-1) per telemetry record |
| Remediation Classifier | `sklearn.ensemble.GradientBoostingClassifier` | `vm_events_remedies_train_8000.csv` merged with monitoring data | Predicts `recommended_remediation` action per anomalous vector |

Features: `cpu_utilization_pct, memory_utilization_pct, disk_utilization_pct, network_in_mbps, network_out_mbps, disk_iops, latency_ms, packet_loss_pct, temperature_c`

## Priority engine

Business-impact priority (P1-P4) is **config-driven**, not hardcoded — edit
`backend/config/priority_rules.yaml` to change thresholds or add a
cross-layer boost rule (e.g. "CPU >=85% AND latency >=400ms simultaneously => P1")
without touching code or redeploying the model.

## Evaluating against the official test set

The 2000-row test set ships as a password-protected archive
(`backend/dataset/Data set/test_data_protected.zip`) per the guardrails.
Once the organizers release the password:

```bash
cd backend
unzip -P <password> "dataset/Data set/test_data_protected.zip" -d "dataset/Data set/"
python evaluate.py
```

This computes detection precision/recall/F1, the remediation
match-rate against `recommended_remediation`, and a single weighted score
(`--weight-detection` / `--weight-remedy`, default 0.6/0.4), saved to
`backend/eval_results.json`.

## Operator feedback -> continuous retraining

1. In the Incidents view, mark an incident **True Positive** / **False Positive**.
2. This calls `POST /api/incidents/{id}/feedback`, which buffers a labeled
   feature vector in `MLEngine`.
3. Trigger retraining from the Models page ("Retrain") or `POST /api/models/retrain`.
4. `MLEngine.retrain_model()` re-fits the Isolation Forest on the training
   set plus buffered feedback and reports before/after precision, recall, F1.

## Repo layout

```
backend/
  main.py                 FastAPI app, REST + WebSocket endpoints, real /health
  ml_engine.py             IsolationForest + GradientBoosting training/inference/retrain
  ingestion.py             Producer + validator/consumer + Dead Letter Queue
  priority_engine.py       Config-driven P1-P4 classification
  correlation.py           Cross-layer VM+app signal correlation
  database.py              In-memory state (VMs, apps, incidents, audit log)
  evaluate.py              Test-set precision/recall/remediation-match scoring
  config/priority_rules.yaml
  tests/                   pytest suite
src/                       React + TypeScript dashboard (Vite)

demo_e2e.sh                 End-to-end validation script
```
